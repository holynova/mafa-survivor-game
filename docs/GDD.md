# 玛法幸存者
> 游戏设计文档（GDD）+ 原版美术资源需求 + 分阶段开发计划 | V1.0 | 2026-10-26

产品定位：基于经典《热血传奇》1.76 三职业、技能、装备与怪物语汇的单机幸存者游戏。战斗规则改为自动施法与 CD，保留经典职业辨识度；借鉴《土豆兄弟》分波次商店、可累积被动道具与升级决策。

文件属性：产品设计基线 / 非代码实现 / 数值均为可调的首轮提案。版本：GDD V1.0（2026-10-26，整合第14.6—14.16节美术资源与Codex交接要求）。所有以“经典资料”标记的原始内容来自参考来源；以“设计值”标记的系本项目新规则。


## 0. 阅读说明与决策基线

| 标记 | 含义 | 如何处理 |
|---|---|---|
| 【经典】 | 资料可核对的原技能/装备/怪物名称或效果 | 制作时再次与目标客户端及合法素材清单核验 |
| 【设计】 | 本游戏的机制、公式、CD、数值、成长、掉率 | 必须通过试玩及自动化模拟后再锁定 |
| 【待核】 | 1.76版本内部/私服资料相互矛盾 | 默认不进入首发；资料核准后按版本开关添加 |


### 0.1 核心已定决策

- 先按“三职业经典 1.76 核心池”落地：法师14、道士13、战士6；气功波等版本边界技能设扩展开关。
- 全部原版候选技能均可获取，但单局技能格最多6个；普通攻击独立于主动技能格。
- 无限 MP：不保留蓝量资源管理；各技能独立CD，自动释放；瞬息移动等可手动触发。
- 不添加原创法术名字、技能进化大招和自造元素反应；升级只强化已有技能（数量/范围/倍率/冷却/持续/召唤上限等）。
- 原版装备仍按武器、衣服、头盔、项链、左右手镯、左右戒指固定 8 槽装备。
- 局内通用道具不占装备栏、可持有大量重复项，但强项软上限/硬上限/唯一限制。
- 局内升级三选一既能强化技能，也能选通用属性；每屏保证适度混合。
- 波次战斗 12×75 秒=15 分钟；11次暂停计时的商店；最后一波出Boss。
- 金币与经验局内清零；结晶与内容解锁跨局；本局掉落的大量装备不直接跨局带入。
- 原版地名、怪名、装备名在内部代号使用；未经授权不将原版图片、音频或商标投入公开发行。
- **美术优先级锁定：正式美术优先使用来源明确、许可允许的《热血传奇》历史原始资源；不得擅自 AI 生图、原创替代或伪造美术；详见第14.6—14.16节。


### 0.2 设计目标与不可做清单

| 目标维度 | 可验收定义 | 明确不做 |
|---|---|---|
| 经典感 | 战法道技能名与主要职责、经典装备物件、地图与敌人阵营辨识 | 原创雷火联动、元素反应套装、现代幻术职业 |
| 一局成长 | 第3分钟形成至少2技能组合；第9分钟形成清晰流派；第15分钟有鲜明输出和生存取舍 | 无脑无限叠施法速度直到0CD |
| 中等难度 | 普通难度测试玩家可逐步形成约70–85%通关率区间，需收集样本验证 | 用随机秒杀或纯堆血量代替难度 |
| 可开发 | Phaser + TypeScript 浏览器原型优先；可单机存档 | 服务器、PVP、充值、MMO社交、锻造概率玄学首发 |
| 资源安全 | 资源适配抽象层、合法素材替换容易 | 把GitHub包含原版图片误认为拥有二次发布许可 |


## 1. 游戏规则与完整循环


### 1.1 单局节奏

| 时间(战斗秒) | 事件 | 玩家决策 | 目标 |
|---|---|---|---|
| 00:00–01:15 | 第1波新手怪、保底起始输出技能 | 移动、收集、第一次升级 | 立即理解自动攻击/收集 |
| 01:15–03:45 | 第2–3波、开放商店 | 金币买道具 vs 攒钱；第一次装备替换 | 清怪能力形成 |
| 03:45–07:30 | 第4–6波、第一只精英 | 单体、群攻、防御三者取舍 | 不能只堆一个技能 |
| 07:30–11:15 | 第7–9波、地图机制出现 | 速度/拾取/续航/技能专精 | 构筑成形但仍有短板 |
| 11:15–15:00 | 第10–12波、13:45前后出现BOSS | 决定最终技能路径与保命装备 | 激烈但不无解的末段 |

【设计】每次75秒结束触发商店（暂停战斗计时）。总计12波，在第12波结束时判定Boss与通关；Boss建议第12波第25秒左右进场，并在第15分钟强制结束逻辑（Boss未死按失败或超时结算）。单局实际墙上用时高于15分钟，因商店暂停。


### 1.2 核心状态机

```ts
Lobby → CharacterSelect → Loading → WaveActive → (LevelUpPaused)* → WaveResult → ShopPaused → WaveActive … → Boss → Settlement → Lobby
失败分支：WaveActive/Boss → Death → Settlement；存档写入先入式事务，避免结算重复领取。
```


### 1.3 掉落收集优先级

- 敌人死亡：经验球必掉（允许若干敌人合并经验实体）；金币按固定概率掉落；精英掉装备/技能书奖励或宝箱。
- 地面金币/经验采用自带生命周期；结束时未拾取金币自动回收50%并损失50%，经验残留在波次结束时自动结算100%以减少成长断档。
- 拾取半径决定吸附触发距离，不改掉落概率，也不增加金币数量；拾取强化本身不得重复增加“掉落率”。
- 掉落对象池与拾取合并，单位对象上限阈值触发合并（例如>300掉落物合并成堆），不可造成卡死。


### 1.4 本局和局外的边界

| 内容 | 局内 | 局外 |
|---|---|---|
| 技能 | 本局通过三选一获得与升级；结束清除 | 技能图鉴及可抽取权限保留 |
| 装备 | 本局穿戴、替换、卖出；结束清除 | 装备图鉴解锁/展示保留，装备数值不保留 |
| 金币 | 商店花费；无法负数；结束清零 | 不转换为永久金币，避免“囤积滚雪球” |
| 经验 | 玩家等级和技能成长选择 | 结束清零 |
| 玛法结晶 | Boss/里程碑结算获得 | 开启地图、外观、技能池与少量上限可控天赋 |
| 普通道具 | 无限格持有，当前局累计 | 不跨局 |

### 2.3 属性计算优先级与防无敌公式

```ts
rollStat = lerp(min, max, seededRandom(luckBias))
rawDamage = skillBase + rollStat × skillCoefficient
attackDamage = rawDamage × (1 + sum(additiveDamageBonuses)) × multiplicativeSkillFactor
mitigation = defenseRoll / (defenseRoll + 22)
finalDamage = max(1, round(attackDamage × (1-mitigation) × (1-otherReduction)))
overallEffectiveReduction = min(0.65, 1-finalDamage/max(1,attackDamage))
netDamage = max(1, ceil(attackDamage × (1-overallEffectiveReduction)))
finalCD = max(skillMinCD, baseCD × (1-min(0.40,effectiveCDR)) × skillLocalFactor)
```

【设计】22为防御敏感度初始参数；所有防御/魔法盾/格挡叠加后的最终总减伤最多65%。最终单次命中至少造成1点伤害（Boss可另设置最小比例伤害）。技能数量倍率必须与目标数量、实际命中次数分离：多个雷击目标不是同一目标承受多次，除非技能明确规定。

【设计】所有属性均通过同一StatPipeline重算：基础 → 装备 → 无格道具 → 本局升级 → 限制与曲线 → UI。禁止每次穿戴直接永久修改基础值，杜绝穿脱刷属性。


### 2.4 通用属性软上限与代码定义

| 属性 | 原始累加 | 软上限后计入方式 | 硬上限 |
|---|---|---|---|
| 移动速度 | 装备+道具+升级百分比 | 超过20%部分×0.5 | +35% |
| 拾取范围 | 超过80%部分开始递减 | 超过80%部分×0.5 | +150% |
| 全局CDR | 超过20%开始递减 | 超过20%部分×0.5 | 40% |
| 技能半径 | 超过20%开始递减 | 超过20%部分×0.5 | +35% |
| 金币获取 | +20%前全额 | 超过20%部分×0.5 | +40% |
| 经验获取 | +25%前全额 | 超过25%部分×0.5 | +50% |
| 闪避 | 正常累加 | 可线性至上限 | 35% |

公式示例：有效拾取加成 min(150%, min(80%, raw) + max(0, raw−80%)×0.5)。超上限的同类纯道具不再入店；混合属性道具仍可出现但 UI 标记该词条已达上限。


### 2.5 无限MP的三项边界

- 魔法盾不再通过MP消耗维持，而是按「持续6秒/总CD15秒/减伤初值20%」运作；技能强化上限35%，在CD上限也不可永久覆盖。
- 护身戒指原版的“以MP承伤”规则在无限MP方案中失效；本游戏改为“获得相当于最大HP 25%的可消耗护盾，脱离受击后20秒恢复”，每波有固定次数限制。标注为【改编】；若追求严格原版可直接不进首发。
- 所有技能至少0.35–0.65秒物理发射调度冷却（按技能类型设定），从引擎角度拒绝无限0CD，多个技能进入优先级队列分帧释放。


## 3. 技能系统规则（全职业通用）


### 3.1 选择、升级和触发

- 本局有6个技能槽。升级候选可包含「新技能」「升级已有技能」「通用属性」。到达第3波前保证至少获得两个进攻手段。
- 技能可升至 Lv3，Lv1是原版基础职责，Lv2/Lv3分别选择一个强化分支；同技能一个等级不能重复领取。
- 同一技能的数量、范围、CD等强化仍沿用原版名字和主要动作，不产生原创终极技。
- 默认所有已装备技能独立CD并自动选目标；需要策略和安全性的瞬息移动/野蛮冲撞允许设置自动/手动，手动使用不影响冷却。
- 攻击型技能可考虑「自动优先级」：低血精英 > 最近可命中敌人 > 最密集群怪；治疗型技能在HP<75%时触发；防御型技能在触发窗口或来袭时施放。
- 怪物招募/召唤使用清晰名单和角色等级权重；Boss、剧情对象、精英默认不可诱惑；敌人一旦变友军不可继续结算敌方掉落。


### 3.2 施法冲突优先级

| 类别 | 排序 | 避免的问题 |
|---|---|---|
| 求生 | 瞬息移动手动 > 即将受击抗拒/野蛮 > 魔法盾/治疗 | 死亡瞬间仍去释放火球 |
| 召唤与增益 | 无宝宝先召唤；过期的护盾/战甲再补 | 每帧重置召唤CD |
| 伤害 | Boss单体、精英优先；群体技能按潜在总伤害选择 | 火墙铺在空地/雷电术打无威胁怪 |
| 投射 | 同一发射tick最多2个高成本动画，其他技能排队<=100ms | 6技能同帧爆发卡顿 |


## 4. 法师技能完整规格（14项）

【经典】技能池按1.76通行技能表共14项；【设计】CD、攻击范围强化、触发阈值、数值属于本项目候选配置。每项技能都可装入6个格子，不存在“法师只能学4种”。

| 技能 | 经典定位 | 基础CD | 自动触发/目标 | Lv2/Lv3可选方向（候选池） | 必须测试的限制 |
|---|---|---|---|---|---|
| 火球术 | 基础单体火系弹道 | 1.1s | 最近可见目标 | 伤害+22%；额外火球+1（不同目标）；弹速+30% | 基础技能需避免被高级大火球完全淘汰：CD更短 |
| 抗拒火环 | 近身击退，不造成伤害 | 11s | 周围接近威胁 | 击退半径+20%；冷却-15%；击退强度+20% | 仅普通/满足等级的敌人有效；Boss免疫 |
| 诱惑之光 | 招募适用怪物 | 7s | 地图上可诱惑目标 | 成功率+15%；上限由2增至3只；宠物伤害+20% | 先天最高5只；失败有CD，不可诱惑Boss |
| 地狱火 | 向前五格直线火焰 | 2.2s | 面对敌群方向 | 火焰宽度+15%；伤害+22%；射程+2格 | 直线技能；不是地面持续火墙 |
| 雷电术 | 单体落雷 | 1.35s | 威胁最高目标 | 同时攻击目标+1；伤害+25%；CD-12% | 多目标独立，避免同一Boss多次命中 |

### 4.2 法师关键机制实施细节

- 诱惑之光：必须定义敌人种族级别、可诱惑标签、诱惑概率、每次尝试CD、招募上限(初期2、培养后5)、怪物仇恨转换、目标丢失、宝宝死亡与掉落归属。
- 火墙：不超过4片独立区域；相同区域合并伤害tick，不按每帧结算；大型Boss站立火墙不触发无限叠伤。
- 魔法盾：减伤20–35%，持续6–7秒，总CD15秒；不是永久保护膜，受全局冷却限值和总承伤下限约束。
- 圣言术：小怪按基础成功率±怪物等级修正；精英/Boss不秒杀，可换成不死系额外伤害15%上限。
- 瞬息移动：随机安全点、禁止传出地图/穿到障碍里/传到Boss体内；玩家手动按空格可触发，默认自动逃生开关可禁。

## 6. 战士技能完整规格（6项）

【经典】战士核心 6 项：基本剑术、攻杀剑术、刺杀剑术、半月弯刀、野蛮冲撞、烈火剑法。不会凭空添加旋风斩等新法术。战士技能池恰好6项导致“技能槽取舍”较弱，因此战士的策略主要来自强化选择与装备，在灰盒阶段专项A/B测试战士4槽模式；正式规则仍暂定6槽统一。

### 6.1 战士的自动战斗细节

- 角色自带的“挥砍普攻”不占槽；基本剑术作为可选择被动独占技能槽。
- 野蛮冲撞可通过按键触发，自动模式只在被包围/血量低/可冲出拥挤区时发起，禁止自动冲到Boss身后接高伤害。
- 半月是面前扇形技能而不是全屏旋转；当玩家与敌人夹角变化时，攻击朝向由移动方向和敌群目标共同决定。
- 烈火剑法修改下一次普攻的伤害，不在每次触发时复制为一条额外投射物。
- 刺杀提升直线打击价值，地图中应有狭长通道和成列敌人。

### 8.3 数值政策

- 武器、衣服、首饰的 DC/MC/SC/DEF/MDEF 尽量参照经典范围；本项目还要缩放到15分钟战斗，故角色基础值和伤害系数另设。
- 史实装备数值必须另建 classicStats 校验库，禁止直接从玩家社区的私服改数拿来标为官方。
- 除经典属性之外，移速/拾取/CD等一律标注为“本项目词缀”；在装备总掉落中出现概率≤15%且倍率低于无格道具，防止装备沦为极品功能堆叠。
- 经典特殊装备如麻痹/复活/隐身/传送/护身只保留可平衡的原理；出现概率极低，并有唯一或每波触发限制。
- 装备换装时所有属性从完整持有状态重新求值，禁止换装点击时永久增益。

### 9.3 无格道具的交易与叠加

- 普通道具可无限次买入但受有效属性上限，超限后该纯道具不再刷新；混合道具在某一词条触顶时只对剩余词条生效。
- 商店每次4个商品格，至少1个无格通用强化；锁定商品占保留格，最多锁2个，不收维护费。
- 道具自动入“被动列表”；UI按type聚合显示×N，可展开查看每件购买顺序/数值，调试支持溯源。
- 唯一装备与特戒不能利用掉落、交易、同波重复刷出超过唯一限制；出售后才允许再次持有。
- 带负面属性的高收益道具为扩展版本，不在MVP加入，降低平衡空间。

| 来源 | 经验/金币 | 装备/宝箱 | 保护与限制 |
|---|---|---|---|

### 10.6 极端玩家经济测试

- 全堆“金币强化”：以1000个战斗种子模拟其第1–12波净收入与商店总采购，比较普通均衡流，若平均购买力高出>25%则下调金币增益。
- 全堆“拾取范围”：确认每波拾取量增长与被动次数合理，收入受掉落总量约束，不随pickupRadius二次乘系数。
- “卖出—买入—锁定—重掷”：对每一商品交易状态保持immutable itemInstanceId，断言无法负价/重复出售。
- 死亡/断网存档：结算先加transactionId，二次进入同一次结算不重复发放永久结晶。

### 14.5 美术资源管线与版权闸口

1. 调研阶段：列出合法可用素材来源、项目内允许开发用途、发布日期与授权文件；网上存在资源仅证明可获取，不证明商用许可。
2. 解析阶段：WIL/WIX等在法律许可边界内导出为PNG；构造 animations.json（动作、方向、帧、帧速、原点）。
3. 打包阶段：按角色/敌人/场景建立纹理图集，生成atlas.json；字段校验并追踪srcAssetLicense。
4. 运行阶段：怪物碰撞盒与美术原点分离，数值与贴图热替换。
5. 发布审查：未经授权的原版角色、地图贴图、UI、音乐、商标不能随可下载客户端/开源仓库直接分发；替换为授权素材或取得许可。

【法律风险】公开运营使用《热血传奇》资源存在著作权侵权风险；“GitHub里能下载”不构成授权。官方检察机关公布过非法使用传奇素材搭建收费私服的相关判决。本文是产品设计文件，不是对版权可用性的法律意见。


### 14.6 原版美术优先原则与不可退让的设计约束（新增）

> **产品负责人明确要求：游戏的正式视觉资源，优先使用网络上《热血传奇 / Legend of Mir 2》历史客户端或保留原版素材的项目资源。除非客观必要，不自行绘制、新造、AI 生成或购买风格近似的替代图片。** 此处“优先原版”指画面美术方向，不意味着可不经授权使用或公开分发第三方资源。

| 原则 | 必须遵守 | 不应发生 |
|---|---|---|
| 风格 | 人物、怪物、技能、物品、地形优先采用来源明确的经典原版美术 | 用 AI 生成“传奇风”人物、混入异质现代图标 |
| 版本 | 玩法目标为经典 1.76；资源仓库可能属于 1.45 或其他版本，必须建立版本差异表 | 误把旧版/私服修改版标成标准 1.76 |
| 命名 | 同一资源只绑定已核验的技能、怪物与物品 ID | 仅凭文件名猜测精灵的归属 |
| 处理 | 允许切帧、裁边、透明化、图集、无损格式转换、锚点修正 | 为“更现代”擅改角色轮廓、造型、颜色与动作本体 |
| 空缺 | 开发阶段仅允许明显的几何调试占位；标记缺失资源，不得作为正式素材 | 没找到资源就悄悄生成一张相似替代图 |
| 授权 | 逐项登记来源与可使用、修改、分发的权利依据；公开版本仅打包已获相应许可的资产 | 以“GitHub 公共仓库”或解析器开源协议替代美术授权 |
| 依赖 | 美术源文件与游戏逻辑解耦，构建时根据许可状态筛选 | 将来因权利问题无法移除原素材或替换贴图 |

**重要裁决**：若确实无法取得部分原版素材的公开分发许可，应把正式发布标记为 `BLOCKED_BY_ASSET_RIGHTS`，向负责人说明具体缺口；未经决定，不得擅自改成自创视觉风格，更不得打包无授权原版图片。私下测试也不能笼统认定天然合法，应具体评估来源和授权条件。

### 14.9 各职业原版素材清单与程序对应关系

#### 14.9.1 法师 P1 / P2 必需

1. **角色外形**：法师默认造型、起始衣服、基础武器；移动时角色与武器图层关系应与源资源一致。
2. **动画**：`idle`、`walk`、`cast`、`attack`、`hurt`、`death`；方向数和每方向帧数保留原始信息，缺少时记录 `MISSING_FRAMES`。
3. **初始技能**：火球术、雷电术、火墙等使用真实技能效果帧；如原文件不是独立完整特效图，可按源文件图层组合还原，不自行设计新技能视觉。
4. **防御/控制**：魔法盾、抗拒火环、诱惑之光、瞬息移动必须能在画面中清楚辨认释放和生效反馈；自动施法 CD 不能因帧数短而不可见。
5. **其余技能**：地狱火、大火球、爆裂火焰、疾光电影、地狱雷光、圣言术、冰咆哮必须与第 4 章名称/逻辑一一对应。若资源缺失，逻辑仍可开发，但正式发布前不能靠 AI 造出“看起来像原版”的素材补齐。

#### 14.9.2 道士 P3 必需

- **角色**：道士衣服、法器/武器外观及完整移动/施法/战斗动作。
- **技能**：治愈、群体治疗、灵魂火符、施毒、幽灵盾、神圣战甲、隐身、集体隐身、困魔咒、召唤过程、心灵启示。
- **召唤物**：骷髅与神兽必须有召唤/站立/移动/攻击/死亡的可用动画。若原素材中缺特定召唤出现动画，优先查询其他保留原版素材的项目，而不是自行重画。
- **异常状态**：红/绿毒、隐身、增益效果尽量从真实客户端效果帧提取；程序可控制透明度、粒子数量、层级，但不得凭空增加新美术概念。

#### 14.9.3 战士 P3 必需

- **角色**：战士甲胄、挥砍、移动、受击及死亡动作，与武器图层正确叠加。
- **技能**：攻杀、刺杀、半月弯刀、野蛮冲撞、烈火剑法的原版攻击动作或特效；基本剑术通常是属性/命中机制，不要求硬造独立视觉动画。
- **空间对应**：半月必须依人物朝向呈扇面，刺杀保留直线距离特点，野蛮冲撞的平移与帧同步，烈火的火焰特效附着在武器攻击帧上。

### 14.10 原版素材版本兼容与素材验真

同名素材在不同客户端、版本、复刻工程中可能存在比例、帧序、调色板、坐标和动作差异。每条资源至少写入：

- **内容真伪**：是否实际为传奇旧客户端内容，还是复刻工程作者新画、私服改色/混包、AI 生成。
- **来源链**：项目网址 → 仓库提交或发行版 → 原始文件相对路径 → 原始文件校验值（SHA-256）。
- **版本**：`1.45` / `1.76` / `unknown` 等，不知道就写 `unknown`，不做推断。
- **配套性**：人物与服装、武器、技能是否属于可兼容的版本组；不混用明显不同画风。
- **合法性**：版权归属、权利证据、是否允许复制、修改、衍生、内部测试、开源分发和商业发布，分别记录。
- **可用性**：真实帧数、八方向完整度、存在的角色动作、透明通道、原点、法术命中点、素材破损情况。

版控策略：`base_mir_version = 1.76` 指**游戏玩法**参考版本；`source_asset_version` 是**每件素材自己的来源版本**，两者不得混淆。允许单一项目出现不同版本资源，但必须标记差异，不能将未经验证的资源一律标称“1.76原画”。

| `permission_pending` | 找到了文件但权利依据不充分 | 否 |
| `blocked` | 明确没有许可、文件不可得或许可不兼容 | 否 |
| `authorized_internal` | 有明确允许当前内部测试范围的依据 | 否；还要看是否具备公开分发权 |
| `approved_redistribution` | 已确认可按具体条件修改/打包/公开分发 | 是，须同时符合署名、非商业等许可条件 |

**禁止事项**：不能因 GitHub 项目显示 `MIT` 就把其含有的《传奇》纹理作为 MIT 图像；不能把 `source_path`、版权方或授权证据设为编造的“默认值”。缺失字段用 `unknown` / `NEEDS_INVENTORY`，并阻止进入公开资源包。

### 14.12 WIL / WIX 到 Phaser 的标准接入流程

1. **获取并冻结源**：对候选仓库读取 README、LICENSE、目录、特定 revision；记录 SHA/哈希；若文件无法合法取得则标记阻塞。
2. **识别格式**：辨别 WIL/WIX、BMP、PNG、地图专用格式、音频；选择可审查的现有解析工具，先用少数样本验证像素、透明度、帧索引是否正确。
3. **资源归属识别**：建立“源帧索引 ↔ 原版对象/动作/方向”的显式映射；严禁随意按连续帧号拼接成动作。
4. **解包与转换**：有权处理的资源导出为透明 PNG / WebP 图像帧；保留不缩放的主资产，并记录来源文件/帧索引；尽量使用最近邻采样，避免模糊。
5. **动画整理**：一个动作对应方向列表、帧号、帧时长、渲染原点、命中事件帧、层级信息；角色是否真有 8 个方向由源文件核验，不足则登记缺口。
6. **图集生成**：按分类打包 Texture Atlas，消除重复透明边，但维持原偏移；生成 `atlas.json`、`animations.json`、`collision.json`；图集分组避免整图超纹理限制。
7. **加载和映射**：统一通过 `AssetRegistry` 以逻辑 `asset_id` 读取，游戏技能/装备只引用 `asset_id`，不硬编码源文件路径。
8. **视觉核验**：实际展示角色八方向走动、攻击、技能释放、怪物死亡、掉落拾取、遮挡和地图层级，人工检查错帧、裁切、方向反转、闪烁。
9. **版权过滤构建**：构建脚本只打包达到目标发布所需授权状态的资源。未经许可的源文件不提交公共 Git 仓库，不上传公开 CDN，不嵌入安装包。

建议工程目录（示意，不代表实际已经存在）：

```text
assets-source/                  # 仅存有相应存储权限的原始包，不进入公共仓库
  mir2/<source-id>/             # 各来源隔离，版本和出处明确
scripts/assets/
  inspect.ts                    # 列出候选资源元数据
  extract.ts                    # 解析/导出（只处理许可允许的源）
  pack.ts                       # 纹理图集和动画数据
  validate.ts                   # 清单、帧完整性和权利闸口校验
public/assets/mir2/            # 仅装配符合当前目标许可条件的生成资源
src/game/assets/
  AssetRegistry.ts
  assetConfig.ts
  animationConfig.ts
  renderLayers.ts
  debugFallback.ts               # 仅内部调试使用
assets-manifest/
  manifest.csv
  build-report.json
```

**渲染约束**：优先最近邻像素采样；统一世界单位/瓦片坐标；人物底部脚点定位（例如通过元数据保存 `originX/originY`，不全局写死）；遮挡层与怪物排序独立于碰撞盒；攻击范围以逻辑几何体计算，不以特效 PNG 透明面积判定。摄像机缩放、不同分辨率和 CSS 像素缩放不得导致动作抖动。

### 14.13 高密度幸存者场景的性能与可读性规范

| 问题 | 实施要求 | 验收方法 |
|---|---|---|
| 同屏数百敌人 | 对象池、复用动画、渲染批次、空间分区；远处怪物与掉落可进行合并或降频 | 目标 300 怪 / 100 投射物 / 500 掉落，性能测试优先 PC 60FPS |
| 经典特效遮挡玩家 | 不改特效原始形象，优先通过层级、渲染优先级和有限显示策略控制 | 火墙、冰咆哮、地狱雷光叠加时能看到角色、敌方危险区 |
| 动画帧错位 | 帧原点和每帧偏移做数据校验 | 同一角色往八方向走、停、施法时脚点不跳跃 |
| 地图错层 | 地面/障碍/角色/遮挡的深度规则显式配置 | 玩家走到树后/墙后遮挡逻辑正确 |
| 掉落太密 | 合并逻辑对象，显示数量和实际金币结算一致 | 不因视觉合并导致金币多给或少给 |
| 不同源版本像素比例 | 分组标准化世界渲染比例，但原始帧不拉伸插值 | 同一场景怪物身高和主角比例一致 |
| 音频过量 | 同类型音效限流/并发混音上限 | 多个怪同时死亡没有爆音；资源版权未清则保持静音 |

性能目标受测试硬件、屏幕分辨率和浏览器影响；“300 怪60FPS”属于设计验收目标，不代表已经通过测试。
